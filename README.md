# GitHub ZIP Pusher

تطبيق Flutter لأندرويد: إدخال التوكن → إنشاء مستودع جديد (أو اختيار مستودع موجود) → اختيار ZIP → رفعه في commit واحد عبر Git Data API.

## التشغيل
```bash
./setup.sh                 # flutter create + الصلاحيات + pub get
flutter run                # تجربة على جهاز
flutter build apk --release
```
- الـ workflow يبني بـ Flutter **3.47.8**؛ استخدم الإصدار نفسه محليًا لنتائج متطابقة.
- معرّف التطبيق الافتراضي `io.github.zippusher.github_zip_pusher`. لتغييره: `APP_ORG=io.github.myname ./setup.sh` (قبل أول تشغيل، فـ `flutter create` لا يغيّر `android/` الموجود). تغيير المعرّف يجعل أندرويد يعامل التطبيق كتطبيق جديد: يُثبَّت بجانب القديم ولا ينقل التوكن المحفوظ.

## كيف يعمل الرفع
- **مستودع فارغ:** الـ Git Data API يرفض العمل عليه (409)، فيُنشأ أولًا commit تمهيدي (`Initialize repository`) يضيف `.gitkeep` عبر Contents API، ثم يُبنى commit الاستيراد (`Import project from ZIP`) فوقه بشجرة لا تحوي هذا الملف. النتيجة سجل من commit-ين، وآخر commit لا يحوي `.gitkeep`.
- **مستودع موجود:** يُضاف commit جديد فوق الفرع الافتراضي؛ تُستبدل الملفات ذات المسار نفسه وتبقى بقية الملفات. يعمل أيضًا مع مستودعات المنظمات التي لك فيها صلاحية كتابة.
- **ما لا يُرفع:** مجلدات `.git/`، والروابط الرمزية، والمسارات الخطرة (Zip Slip)، والملفات المكررة داخل الأرشيف، وما يتجاوز الحدود أدناه. يُعرض ما يُتجاهل بسببه، عدا ملفات النظام (`__MACOSX` و`.DS_Store` و`Thumbs.db` و`desktop.ini`) فتُتجاهل بصمت.
- **تنبيه الأسرار:** قبل الرفع يُحذَّر من ملفات تبدو أسرارًا بحسب اسمها فقط (`.env` و`*.jks` و`key.properties`…). المحتوى لا يُقرأ.
- **الحفاظ على التنفيذ:** `gradlew` والسكربتات تُرفع بالوضع `100755`. وتُفحص CRC لكل ملف عند الفك.
- **`.github/workflows`:** ترفضها GitHub بلا نطاق `workflow` (كلاسيكي) أو صلاحية Workflows (Fine-grained). مع توكن كلاسيكي بلا النطاق يعرض التطبيق استبعادها قبل الرفع؛ أما Fine-grained فلا يمكن فحص صلاحياته مسبقًا، فيظهر تلميح عند الرفض.
- **فشل الرفع:** إن أنشأ التطبيق المستودع ولم يصله أي ملف، يظهر زر لحذفه (يحتاج `delete_repo` أو Administration: write).

## الحدود
| الحد | القيمة |
|---|---|
| حجم الملف الواحد | 100MB (الأكبر يُتجاهل) |
| المجموع بعد الفك | 500MB (أكثر منه يوقف العملية) |
| عدد الملفات | 6000 (الزائد يُتجاهل) |

- **دمج الملفات النصية:** ملفات UTF-8 حتى 256KB تُرسل داخل طلب الشجرة نفسه بدل طلب لكل ملف، وتُقسَّم الشجرة على دفعات (2MB أو 1000 مدخل). الملفات الكبيرة والثنائية لكل منها طلب blob وتُرفع بثًّا من القرص.
- **حد المعدل:** تُعاد المحاولة عند 429 و403 (حد المعدل) و5xx وأخطاء الشبكة. عند حد المعدل ينتظر التطبيق حسب `retry-after`، وإلا حتى `x-ratelimit-reset`، وإلا دقيقة فأكثر؛ وإن زاد الانتظار عن 10 دقائق توقف وأخبرك بموعد المحاولة. بين الطلبات الكاتبة فاصل ثانية.
- GitHub تحدّ الطلبات المنشئة للمحتوى بنحو 500 في الساعة (حسب توثيقها)، فرفع آلاف الملفات الثنائية قد يستغرق ساعات.

## صلاحيات التوكن
- **كلاسيكي:** `repo` (أو `public_repo` للمستودعات العامة فقط)، و`workflow` إن كان الأرشيف يحوي `.github/workflows`.
- **Fine-grained:** Administration + Contents (وWorkflows لملفات `.github/workflows`)، ويجب أن يشمل المستودع الهدف. صلاحياته لا يمكن فحصها مسبقًا.

## البناء عبر GitHub Actions
1. ارفع المشروع (بما فيه `.github/`) إلى فرع `main`.
2. تبويب **Actions** ← **Build APK**. يعمل عند كل push يغيّر غير ملفات `.md` و`.gitignore` و`LICENSE`، أو يدويًا بـ Run workflow (مع خيار نشر Release).
3. الخطوات: `setup.sh` ← `flutter analyze` ← الاختبارات (إن وُجد `test/`) ← بناء الـ APK.
4. الناتج: Artifact باسم `github-zip-pusher-apk` (ملف ZIP) بداخله `github-zip-pusher.apk`، وعند النشر Release باسم `v1.0.<رقم التشغيل>` يحوي الملف نفسه.
5. **`pubspec.lock`:** إن لم يكن في المستودع، يرفع التشغيل نسخته المولَّدة كـ Artifact باسم `pubspec-lock`. نزّله وأضفه إلى جذر المشروع ليثبّت إصدارات الحزم.

الأمان: الـ workflow للقراءة فقط افتراضيًا، و`contents: write` لمهمة النشر وحدها. الإجراءات مثبّتة بـ SHA كامل ويحدّثها Dependabot شهريًا. ولا يُنشر Release عند تعديل التوثيق وحده.

## التوقيع
الـ APK موقّع بمفتاح debug الافتراضي: يصلح للتثبيت المباشر لا للنشر على Play.

للإصدار النهائي أعدّ التوقيع في `android/app/build.gradle.kts` (أو `build.gradle` في Flutter الأقدم) واجعل بياناته في `android/key.properties` وملف `.jks`؛ كلاهما مستبعد في `.gitignore` فلا ترفعهما. لأن `android/` يُولَّد من جديد في كل بناء عبر `setup.sh`، أضف تعديل التوقيع إلى `setup.sh` أو ضع `android/` في المستودع.

## ملاحظة عند الترقية من إصدار سابق
بعد ترقية `flutter_secure_storage` إلى 11.x لا يُقرأ التوكن المحفوظ بالإصدارات القديمة؛ يمسحه التطبيق تلقائيًا ويطلب إدخاله مرة واحدة. لا بيانات أخرى تتأثر.
